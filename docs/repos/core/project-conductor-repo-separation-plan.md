# Project Conductor Repo Separation Plan

## Status
- Revised: 2026-04-25
- Owner: Architect Agent
- Decision: keep `tv7-conductor` as a standalone runtime repo, but tighten the boundary before decommissioning the old `tv7-core` orchestrator surface.

## Current Finding
The extraction is partially complete:
- `tv7-conductor` contains the runtime package, policies, tests, local Makefile, runbook copies, and `docs/.conductor` state.
- `tv7-core` contains governance docs, roadmap files, shim scripts, `make conductor-*` entry points, and deprecated `orchestrator-*` aliases. Runtime state no longer lives in `tv7-core`.
- The runtime still treats a single `core_dir` argument as the source for roadmaps, state storage, report output, and command working directory. That was workable when the runtime lived in `tv7-core`, but it is now the wrong abstraction.

## Revised Boundary
`tv7-core` owns:
- Canonical roadmap files under `docs/roadmaps/`.
- Cross-repo governance, contracts, repo policy, and operator-facing compatibility entry points.
- Compatibility shims only: `tooling/conductor.py`, `tooling/conductor_run.py`, `tooling/orchestrator.py`, and Make targets that call `tv7-conductor`.
- DeepSeek reusable review workflow and shared repo bootstrap/status tooling that are not part of Conductor runtime.

`tv7-conductor` owns:
- Runtime implementation for plan, seed, expand, execute, review, status, and events.
- Runtime policies and config under `tooling/orchestrator/`.
- Runtime tests and CI for the conductor package.
- Runtime state, events, reports, and execution artifacts under `tv7-conductor/docs/.conductor`.
- Conductor-local runbooks for operators who run the runtime directly.
- Portable install/bootstrap docs and scripts so Conductor can run on any operator machine against any configured workspace.
- Human-in-the-loop developer automation, including isolated worktree/test-environment preparation.

Per-repo product repos own:
- Their implementation, validation commands, and execution artifacts generated by per-repo agents.
- No Conductor runtime code and no duplicated canonical Conductor docs beyond links or short local usage notes.

## Required Path Contract
Replace the single overloaded `core_dir` concept with explicit path roles:
- `workspace_dir`: parent directory that contains all TV7 repos.
- `core_dir`: `tv7-core` repo root, used for canonical roadmaps and governance reads.
- `conductor_dir`: `tv7-conductor` repo root, used for runtime-relative config/tests/docs.
- `state_dir`: conductor state root, defaulting to `tv7-conductor/docs/.conductor`.
- `target_repo_dir`: resolved per repo during execute/review handoff.
- `worktree_dir`: optional isolated checkout used for executing and testing changes without disturbing the human's primary checkout.
- `preview_port`: optional per-task local port override used when a repo exposes a local service preview.

`tv7-core` shims must pass explicit values for these roles instead of relying on `tv7-conductor` CLI defaults.

## Migration Plan
1. Harden shim routing.
   - Make every `tv7-core` `conductor-*` target pass explicit `core_dir`, `conductor_dir`, and `state_dir` values.
   - Add dry-run tests for all shim targets so regressions are visible without touching GitHub.

2. Split runtime path handling.
   - Update Conductor CLI and state store APIs to accept separate roadmap source and state output roots.
   - Preserve backward compatibility for existing `--core-dir` callers during one migration window, but mark it as deprecated once explicit path flags exist.

3. Keep state in the runtime repo.
   - Keep `tv7-conductor/docs/.conductor` as the active state root after path split.
   - Remove generated `tv7-core/docs/.conductor` state from local workspaces; core shims route state writes to `tv7-conductor`.
   - Treat any old `tv7-core/docs/.conductor` copy as disposable generated state unless an operator explicitly exported it before cleanup.

4. Deduplicate docs.
   - Keep canonical architecture decision and governance docs in `tv7-core`.
   - Keep runtime runbooks in `tv7-conductor`, with `tv7-core` linking to them or carrying short compatibility notes only.
   - Remove or clearly label stale duplicate docs after the path contract lands.

5. Finish repo hardening.
   - Add `tv7-conductor` CI for unit tests and lint.
   - Add a conductor package check that imports the runtime from `tv7-conductor` without requiring `tv7-core/tooling/orchestrator`.
   - Move or remove conductor-side tests that cover `tv7-core`-owned DeepSeek shared tooling.
   - Confirm all runtime policies load from `tv7-conductor/tooling/orchestrator`.

6. Add isolated human test loops.
   - Add worktree-backed execution options so Conductor can prepare changes in a separate checkout.
   - Add per-repo preview command profiles with port overrides, for example running a service that normally uses `localhost:5000` on `localhost:5001`.
   - Report preview URL, branch, worktree path, command, logs, and cleanup instructions after each execute/test run.
   - Keep destructive cleanup explicit; never remove worktrees or stop unrelated developer services without operator intent.

7. Make the tool transportable.
   - Document prerequisites and bootstrap steps for a fresh machine.
   - Keep Make targets as the human-facing interface and scripts as implementation details when logic becomes non-trivial.
   - Add a fixture repo validation path proving Conductor can operate outside TV7-specific assumptions.

8. Decommission legacy names.
   - Keep deprecated `orchestrator-*` aliases until two clean full Conductor batches pass.
   - Remove old names only after the integrate stage, runbook validation, and phase gates are green.

## Non-Goals
- Do not move canonical product roadmaps out of `tv7-core` in this pass.
- Do not convert Conductor into a daemon or hosted service.
- Do not remove compatibility shims until clean-batch deprecation criteria are met.
- Do not write new Conductor runtime state into `tv7-core`; core is a governance and shim surface only.
- Do not make isolated preview/test environments replace repo-local CI; they are operator convenience and validation aids.

## Acceptance Criteria
- From `tv7-core`, `make conductor-plan`, `make conductor-run`, `make conductor-status`, and every stage target operate on `tv7-core` roadmaps while writing runtime state to `tv7-conductor`.
- From `tv7-conductor`, direct CLI commands work with explicit `--core-dir ../tv7-core` and the default conductor state root.
- `tv7-core` no longer contains runtime modules under `tooling/orchestrator/`.
- `tv7-conductor` tests pass without importing deleted `tv7-core` runtime modules.
- `tv7-conductor` tests do not import `tv7-core`-owned `deepseek_review_comment.py`, `deepseek_followup.py`, or `deepseek_fix.py`; those stay covered by `tv7-core`.
- Runbooks state the boundary clearly enough that a new operator can tell whether a change belongs in `tv7-core` or `tv7-conductor`.
- Conductor can prepare a task in an isolated worktree, run repo-declared validation commands there, and expose a separate local preview port when the repo declares one.
- Every execute/test handoff reports what changed, where to inspect it, how to run it, which port to open, and what human approval is still required.
